# graph/schema: the typed metamodel of the weave graph

Owner: lane weave, ADR-0089. Design and evidence: [docs/weave/design/metamodel-and-identity.md](../../docs/weave/design/metamodel-and-identity.md). Status: DESIGN. Read by the sibling aspects (`graph/rules/check_catalogue.py`, the human-views and impact-math oracles); no extractor or `eijagraph` module consumes it yet.

## Files

| File | What it is | Edited by |
|---|---|---|
| `metamodel.json` | The single maintained source: node types (id grammar, hash methods, attributes), link kinds (many-sorted signatures, structural cardinality, obligations, anchored ends, propagation direction), hash-method registry, views, owner-vocabulary aliases | a person, through a PR that also bumps `metamodel_version` |
| `node.schema.json`, `edge.schema.json`, `graph.schema.json` | JSON Schema 2020-12 for one node record, one edge record and a whole graph document | generated, never by hand |
| `build_schemas.py` | Generator and `check_metamodel` (coherence of the tables). `--check` fails when a committed file is stale | code |
| `typecheck.py` | Executable definition of the join-level checks JSON Schema cannot express: signature typing, structural cardinality, acyclicity, self-loops, dangling ends, rename validity and termination of the lifted id-level plus path-level rename system (`rename-cycle`). The rule lane's implementation must agree with it | code |
| `identity-vectors.json` | Golden vectors for the canonical writer, domain-separated hashes, edge ids and exported UUIDs. `eijagraph.canon` must reproduce them byte for byte | generated by `python graph/bench/identity_checks.py --write` |

## Use

```text
python graph/schema/build_schemas.py            # regenerate the schemas and the tables below
python graph/schema/build_schemas.py --check    # exit 1 if a committed generated file differs
python -m pytest tests/graph/test_metamodel_identity.py
```

Validation needs `jsonschema` (Draft 2020-12). Without it the tests report a skip, which is NOT_RUN and never a pass.

## Canonical form of a graph document (committed artefacts)

1. Strings, integers with absolute value at most 2^53-1, booleans, null, arrays and objects only. No floats.
2. Serialised as RFC 8785 (JCS): no whitespace, object keys sorted by UTF-16 code units, UTF-8, LF.
3. Absent means default. There is no `null` and no empty container; an optional field has exactly one encoding, which is its absence.
4. Nodes are sorted by `id`, edges by `(kind, from, to, qualifier)`, both by ASCII byte order (ids are ASCII by grammar).
5. No wall clock, time zone, uuid4, random value, host name or absolute path anywhere in the document.

## Versioning

`metamodel_version` is semver. MAJOR: a type, kind or field is removed or renamed, or a signature is tightened so existing graphs become invalid; it needs a migration function and changes every root hash on purpose (the root domain tag carries the major). MINOR: additive (new type, kind, optional attribute, enum value, hash method); it must not change the hash of any existing record. PATCH: text only. Hash method names are immutable: a normalisation change is a new name (`ast-v2`) plus a re-baseline (D-13).
