# Start here

This is the EIJA Studio knowledge base, a Google Cloud Open Knowledge Format (OKF) v0.2 bundle. Start retrieval here, then follow one section at a time.

Every concept page carries a `resource` (a `repo://` URI naming a file or symbol in this repository) and `sources` entries with the SHA-256 of the normalised code or document it describes. `nox -s okf` fails when a page's linked source changed since the page was baselined (STALE) and, after `python -m quality.okf sync` re-baselines the machine-owned parts, keeps failing (NOTES_STALE) while a page's hand-written `## Notes` have not been re-read against the new source: only `python -m quality.okf review` clears that. Hashing is per source: a page's hash covers its own symbol and the private helpers of the same module it reaches, not public callees, other modules or adapter bodies, so a passing gate never proves that every page is true. Machine-owned frontmatter and the blocks between `okf:generated` markers are regenerated by `python -m quality.okf sync`; prose under `## Notes` is human-owned and preserved.

A hash proves that the linked text changed, not that a page is right. Trust tiers come from the `verified` field, count only attestations bound to the page's current prose and source hashes, and `by: human:<id>` is a self-declared label the tool cannot authenticate. No current attestation means unverified.
