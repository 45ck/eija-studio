# Work breakdown: POC and wow demo (approved 2026-09-29)

## Context
All code is on one branch, `integrate/all` (draft PR #29, 641 files vs main), a consolidated snapshot that has never been gated as a whole. Nothing is running. Three read-only surveys of that tree and one architecture design established the ground truth below; the plan is built from that, not from memory.

**Owner decisions (today):**
1. **The POC is domain-agnostic.** A user points EIJA at any repo, given a language/domain pack and a correctly set-up repo, and sees it visualised (language tree, DDD tree, UML/flow, ripple); agents propose via MCP, the kernel checks (formal evidence included), the owner decides. No hardcoded domain language in generic code.
2. **Build the app first, then record the demo, all four flagship scenes** (side-by-side vs vibe coding; agent change as semantic diff + ripple + evidence; drag-and-drop UML updates the software; parallel agents landing safely).
3. **Option D drag:** a drag changes meaning; the kernel accepts or refuses at the drop target (overrides ADR-0061's D-lite).

**Where we actually are (measured on the tree):**
- Kernel is hardwired to the excursion toy domain: `Workflow.id: Literal["excursion"]`, `check_policy` whitelists the exact shape, two hardcoded `SemanticTransaction` kinds, `CANONICAL_OPTIONS` in the kernel (`src/eija_studio/domain/models.py`, `domain/policy.py`). Authority laws are hand-encoded **five times** (SMT, BMC, Bend, TLA+, `policy.py`). 120 vocabulary lines in 19 kernel files; `docs/engineering/GENERALITY-AUDIT.md` exists but its ADR-0153 does not.
- Working and reusable: generated diagrams + semantic diff + ripple (`application/diagrams.py`, `diagram_catalog.py`, golden tests); MCP server (cannot approve/apply); evidence kinds for bend/smt/bmc (`domain/evidence_kinds.py`); OKF code-linking (`quality/okf/codelink.py`: `repo://` URIs, AST hashes); graph reference oracles (`graph/formal/eijaref`, `graph/schema/typecheck.py`, `graph/rules/reference.py`); demos harness + `pr-gif` (958 lines, browser/terminal/publish); HCI harness (19 ratcheted budgets).
- Missing: tlc/property/mutation evidence kinds; smt/bmc evidence snapshots not committed (NOT_RUN on fresh clone); MCP `render` cannot produce mermaid (`mcp_server.py:272` never receives `diagram_renderer`); no e2e test; no working weave slice; no workbench, tree or canvas (design docs only, ADR-0057..0068 proposed); demo registry 0 recorded / 9 blocked.
- Predicted gate breakage: 30 ADRs missing from the index; `docs/adr/00101-*`/`00103-*` five-digit names invisible to `adr_index.py`; `tests/metrics/test_metrics_structure.py:61` syntax error (breaks collection); `MANIFEST.json` 35 mismatches; duplicate PR templates; junk files (`bash.exe.stackdump`, `evidence/*.log`, `evidence/*.png`, `evidence/coverage.json`).

**Constraints:** weekly Claude usage 54% by day 2 (Opus was 72% of spend); 16 GB RAM shared; no CI; restamp and keys deferred by the owner (red banner and NOT_RUN live providers are expected and must be shown honestly); agents never approve or apply.

## Execution model
- **One Workflow per phase**, all on `integrate/all` in `C:\Dev\eija-wt\integrate`, single writer, serial. I read each phase's result and you glance at `/usage` before the next launch. Not one giant workflow: no way to read the budget from inside a script, one failure would block everything, and it would commit demo-phase tokens before the POC's cost is known.
- **Model policy:** Sonnet by default (mechanical WPs, gate fixing, GIFs, write-ups). Opus only for WPs marked *strong* (kernel/law design, canvas semantics, adversarial reviews).
- **Bypass permissions:** your setting, not mine. Start the session in bypass mode so the workflow never stalls on prompts. Safe here: one worktree, the repo hook still blocks force-push/`--no-verify`, and owner-only rules stay in every prompt and are enforced by tests (agent cannot approve/apply).
- **State in git:** every WP is a commit series that ticks a checklist line in PR #29; nothing lives only inside an agent. Every WP lands with its gate and a negative control.
- **Stop conditions in every script:** stop and report if a WP needs an owner-only action, if gate failures are unexpectedly large, or if `main` would be touched with a red gate.
