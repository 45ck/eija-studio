# Ubiquitous language, ontology engineering and DSL tooling: what EIJA should adopt

Lane: weave. Dossier: language-ontology-dsl. Written 2026-09-29. All URLs opened 2026-09-29 unless marked UNVERIFIED.

## Decisions first

1. **Do not adopt a language workbench, an OWL reasoner or a graph database for the ubiquitous language (UL).** The UL is a closed, small, curated set (EIJA has 10 glossary terms today). The problems are naming consistency and drift, not inference. Cost of MPS, Xtext, Langium, OWL or Neo4j exceeds benefit by a wide margin.
2. **Adopt one plain, canonical-JSON term registry** (YAML or JSON validated by the existing Pydantic/JSON Schema stack) whose data model borrows SKOS (W3C Recommendation) label semantics and the Deissenboeck-Pizka bijection rule. Everything else (OKF pages, editor glossary, prose-lint vocab, SKOS Turtle, Context Mapper file) is a **generated, get-only projection** of it.
3. **Link terms to symbols by declaration, not by name inference.** Measured on this repo: only 3 of 10 glossary terms appear as contiguous identifier words in `src/` (section 3). A "term must appear in the name" rule would fail 70% of the vocabulary on day one.
4. **The gate enforces only what is decidable with near-zero false positives:** forbidden surface forms (exact token after a pinned splitter), per-context homonym/synonym bijection, unresolved or stale bindings, and deprecated-term use. Coverage and "unknown vocabulary" are reports, not failures. ML name-consistency models are advisory only (best published F1 in our sources: 67.9%).
5. **Build small, export widely.** Custom code: registry schema, splitter, checker, projections (est. under 800 lines, ADR-0016 justified in section 5). Reuse: Python `ast`, markdown-it-py (OKF lane), the OKF `repo://` link and hash methods, `impact.py` closure. Optional processes: Contextive, Vale, cspell, pySHACL.

## 1. Scope and method

**Question.** How can a UL tree be enforced deterministically across code names, UI labels, diagram labels, tests and docs with low false positives, and what has been measured?

**Method.** Opened: the DDD Reference PDF, W3C SKOS/SHACL/OWL 2/RDFC specs, RFC 8785, the OKF v0.2 spec, the Deissenboeck-Pizka full text, 12 paper abstracts, about 25 repositories (GitHub API metadata, LICENSE file heads, READMEs, latest releases), PyPI metadata, tool docs, the private ProofMap Lite repo (read through the owner's authenticated `gh`), the EIJA repo and sibling worktrees. Ran one local probe (`docs/weave/research/evidence/term_probe.py`, commit ddc43b9).

## 2. Per school: what it gives EIJA

### 2.1 Domain-driven design (Evans, Vernon)

- **What.** Ubiquitous language: "Use the model as the backbone of a language... Within a bounded context, use the same language in diagrams, writing, and especially speech. Recognize that a change in the language is a change to the model." Bounded context: "Model expressions, like any other phrase, only have meaning in context." [DDD Reference, CC BY 4.0](https://www.domainlanguage.com/wp-content/uploads/2016/05/DDD_Reference_2015-03.pdf). Vernon's book was not opened; nothing is claimed from it.
- **Evidence of effect.** A 36-study systematic review reports DDD "effectively improved software systems" but also that "some studies lacked empirical evaluations" ([Ozkan et al., arXiv 2310.01905](https://arxiv.org/abs/2310.01905), abstract). Treat DDD as a design discipline with weak quantitative support, not as a proven metric.
- **Gives EIJA.** The per-context scoping rule. EIJA's context map (ARCHITECTURE.md: Authoring, Execution, Assurance, Governance, Provider integration) becomes the scope key of every term. Cost: none beyond curation. Verdict: adopt the concepts.
- **Tooling.** [Context Mapper](https://github.com/ContextMapper/context-mapper-dsl): Apache-2.0, Xtext/Java (JDK 11+), latest release v6.12.0 (2024-08-30), last commit 2025-07-08; generates PlantUML, MDSL. Verdict: export target (emit a CML context map for architects who use it), never a dependency. Slow-moving, JVM.

### 2.2 Formal naming theory and identifier research

- **Deissenboeck and Pizka** ([full text](https://teamscale.com/publications/2005-concise-and-consistent-naming.pdf); [journal version metadata](https://doi.org/10.1007/s11219-006-9219-1)). Let C be concepts, N names, R a subset of N x C. A name n is a *homonym* iff |C_n| > 1. A naming system is *consistent* iff R is a bijection; an identifier is *concise* iff i(p) = n(c). In Eclipse 3.0M7 (2 MLOC) identifiers are 32.8% of tokens and 71.7% of characters; JDK 1.4.2 has 42,869 distinct identifiers built from 6,426 words. The paper reports a tool (identifier dictionary) but no false-positive rate. **This is the most implementable idea in the dossier**: two exact set checks.
- **Lawrie et al. ICPC 2006** ([abstract via OpenAlex](https://api.openalex.org/works/doi:10.1109/ICPC.2006.51)): over 100 programmers, full-word identifiers give best comprehension, often not statistically different from abbreviations. **Hofmeister et al. SANER 2017** ([abstract](https://api.openalex.org/works/doi:10.1109/saner.2017.7884623)): 72 professional C# developers, words gave about 19% faster defect finding than letters or abbreviations. **Schankin et al. ICPC 2018** ([abstract](https://api.openalex.org/works/doi:10.1145/3196321.3196332)): 88 Java developers, descriptive names about 14% faster on a semantic defect, no effect on a syntax error. Implication: spelled-out domain words in identifiers are worth enforcing; the effect sizes are modest and task-dependent.
- **Feitelson et al.** ([arXiv 2103.07487](https://arxiv.org/abs/2103.07487)): 334 subjects; median probability that two developers choose the same name was 6.9%; an explicit concept-word-name process improved judged quality about 2:1. Implication: without a shared registry, independent authors (human or agent) will diverge; a registry converts free choice into lookup.
- **Butler et al. CSMR 2010** ([abstract](https://api.openalex.org/works/doi:10.1109/csmr.2010.27)): flawed identifiers associate with lower static-analysis quality at method level. Association, not causation. **Abebe et al. SCAM 2011** ([abstract](https://api.openalex.org/works/doi:10.1109/scam.2011.18)): lexicon bad smells impair IR-based concept location on two systems. Relevant to agents: retrieval-based tools degrade on inconsistent vocabulary.
- **Linguistic antipatterns.** Arnaoudova et al. define them as recurring poor naming/commenting choices and provide the LAPD detector for Java ([CSMR 2013 abstract](https://api.openalex.org/works/doi:10.1109/CSMR.2013.28); [catalogue site](https://www.linguistic-antipatterns.com/), which cites a study with 11 professionals and 19 students). The journal follow-up ([EMSE 2016](https://doi.org/10.1007/s10664-014-9350-8)) has an elided abstract; its perception and precision numbers are UNVERIFIED here. Tools found are stale or tiny (site repo last pushed 2022-08-26; a Python detector `woofz/pydeal` has 0 stars, unknown licence). Verdict: inspiration for a small antipattern rule set (name/type mismatch, "get" that mutates); do not depend.
- **Learned consistency checking.** Liu et al. ICSE 2019 report 67.9% F1 detecting inconsistent Java method names ([abstract](https://api.openalex.org/works/doi:10.1109/icse.2019.00019)); Naturalize reports 94% top-suggestion accuracy for identifier names ([FSE 2014 abstract](https://api.openalex.org/works/doi:10.1145/2635868.2635883)). A 67.9% F1 detector is unusable as a merge gate; suggestion quality is usable as an agent hint. Verdict: advisory only.
- **Glossary extraction and traceability.** Arora et al. cluster candidate glossary terms from requirements, with 20 percent or more recall gain over generic extractors in three case studies ([abstract](https://api.openalex.org/works/doi:10.1109/tse.2016.2635134)). Antoniol et al. recover code-to-doc links via IR, premised on meaningful names ([TSE 2002 abstract](https://api.openalex.org/works/doi:10.1109/tse.2002.1041053)). Verdict: use for one-off bootstrap of candidate terms (advisory); IR links are probabilistic and cannot be a gate.
- **BDD.** A survey of 75 practitioners found domain-specific terms a main benefit and that specifications share test-suite maintenance costs ([Binamungu et al., SANER 2018](https://api.openalex.org/works/doi:10.1109/saner.2018.8330207)). Gherkin ([MIT](https://github.com/cucumber/gherkin)) and pytest-bdd ([MIT](https://github.com/pytest-dev/pytest-bdd)) are a possible surface for UL in tests; not needed now.

### 2.3 Controlled vocabularies and ontology engineering (SKOS, OWL, SHACL)

- **SKOS** ([W3C Recommendation 2009-08-18](https://www.w3.org/TR/skos-reference/)). Directly useful integrity conditions: at most one `prefLabel` per language (S14); `prefLabel`, `altLabel`, `hiddenLabel` disjoint on a resource (S13); `related` disjoint with `broaderTransitive` (S27); `broader` is not transitive, `broaderTransitive` is. Documentation properties: `definition`, `scopeNote`, `example`, `historyNote`, `changeNote`, `notation` ([primer](https://www.w3.org/TR/skos-primer/)). **Gives EIJA** the exact label model it needs: prefLabel (the canonical form), altLabel (accepted forms), hiddenLabel (surface forms used in code and ids, for matching only). Cost: none if borrowed as a data model. Verdict: adopt the model, export as Turtle.
- **OWL 2** ([Recommendation 2012-12-11](https://www.w3.org/TR/owl2-overview/)). The [primer](https://www.w3.org/TR/owl2-primer/) states OWL follows the open-world assumption and lacks a unique-names assumption. A closed glossary wants the opposite: absence means missing, different names mean different forms. Verdict: reject as an engine. [OWL-RL](https://pypi.org/project/owlrl/) (W3C software licence) adds inference nobody needs here.
- **SHACL** ([Recommendation 2017-07-20](https://www.w3.org/TR/shacl/); the [1.2 Core draft](https://www.w3.org/TR/shacl12-core/) is a Working Draft dated 2026-09-18, so not yet stable). Closed-world shape checking is the right idea, and validation must not mutate graphs. [pySHACL](https://github.com/RDFLib/pySHACL) v0.40.1 (2026-07-28), Apache-2.0, pure Python on rdflib, [rdflib](https://github.com/RDFLib/rdflib) 7.6.0 BSD-3-Clause. Verdict: optional cross-check of the exported SKOS graph in a `graph` extra or CI job; the primary checks stay native Python because they are about 20 lines each.
- **RDF canonicalisation** ([RDFC-1.0 Recommendation 2024-05-21](https://www.w3.org/TR/rdf-canon/)): isomorphic datasets give the same canonical form; adversarial graphs can be expensive. Needed only if we ever hash a graph; a term registry as canonical JSON avoids blank nodes altogether.
- **LinkML** ([Apache-2.0](https://github.com/linkml/linkml), v1.11.1, 2026-05-20) generates JSON Schema, SHACL, OWL, Pydantic and more from one YAML model, but pulls a large dependency set (antlr runtime, jinja2, graphviz ...). Verdict: inspiration and possible one-off export; adding it duplicates what Pydantic already does for us.
- **Vocabulary quality.** qSKOS found possible quality issues in all 15 vocabularies analysed ([Mader et al., arXiv 1206.1339](https://arxiv.org/abs/1206.1339)). The tool's current status was not checked (UNVERIFIED). Lesson: even curated vocabularies need automated checks beyond the spec.

### 2.4 OKF v0.2 as file-based knowledge

[OKF v0.2 SPEC](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) (repository Apache-2.0, pushed 2026-09-21): a bundle is a tree of Markdown files; only `type` is required; a concept ID is its file path; links are standard Markdown links and "kind is conveyed by prose, not by the link"; broken links are tolerated; producers "MAY include any additional keys". **Consequences:** OKF gives storage, provenance and progressive disclosure but no typed relations, no cardinality, no label uniqueness and no checker. Broken-link tolerance is the opposite of what a language gate needs. So: OKF term pages are a *generated view* (`type: Term`, extension keys `term_id`, `context`, `forms`), while typed relations and the checks live in the registry. The okf lane's `repo://` links with hash methods (including `md-bold-term-v1`, which already hashes `**Term:**` paragraphs like ARCHITECTURE.md's) provide the binding mechanism; this dossier reuses it rather than inventing one.

EIJA's registry is data, not a language, and the Studio already renders it. **Language server for terms:** not needed for v1. ### 2.6 Prior art on enforcing a UL, and ProofMap Lite lessons

- **No measured study of UL-enforcement tools was found** with the means available (see method). The closest practical tools: [3D-Linter](https://github.com/RomanosTrechlis/3d-linter) (Apache-2.0, created 2026-07-14, 0 stars) whose SPEC states the design EIJA would reach independently: exact-token avoid lists with trivial plurals only, "no stemming beyond that, no fuzzy, no embeddings", diff-only gating, reasoned suppressions, tree-sitter declaration awareness planned, "the gate is deterministic; AI is advisory". It has no measurements and plans a paid tier: inspiration, not a dependency. [Koine](https://github.com/Atypical-Consulting/Koine) (Apache-2.0, .NET, active) generates code from a UL DSL: a parallel model source, which AGENTS.md forbids for EIJA.
- **Vale** ([MIT](https://github.com/vale-cli/vale), v3.23.0 2026-09-25; README: sole developer) has `substitution`, `existence`, `consistency` rules and `accept.txt`/`reject.txt` vocabularies ([docs](https://docs.vale.sh/topics/styles)). **cspell** ([MIT](https://github.com/streetsidesoftware/cspell), v10.3.5 2026-09-27) has `flagWords` with `word->suggestion` ([schema](https://raw.githubusercontent.com/streetsidesoftware/cspell/main/cspell.schema.json)). Both are Go or Node binaries: optional generated-config consumers. Whether they skip code blocks by default was not verified.
- **ProofMap Lite lessons (owner's repo).** (1) GAP-030: per-view vocabulary contracts (allowed node labels, allowed edge labels, required refs) checked vocabulary parity, "not full semantic equivalence". Same limit applies to us. (2) GAP-024: contradictions between views were caught by targeted regexes, not in general. (3) GAP-017/018: warnings can be accepted only with `id`, `reason` and a repo-local evidence path that resolves; otherwise they stay active. Reuse this suppression shape. (4) GAP-025/028: SHA-256 snapshots prove freshness, not correctness. (5) GAP-003: regenerating timestamps caused churn; EIJA forbids wall clock in artefacts anyway. (6) 40 change bundles by CHG-040 shows the ceremony risk; keep the language loop to one command.

## 4. Mechanisms

| School | Mechanism | Benefit | Cost | Verdict | Source |
|---|---|---|---|---|---|
| Formal terminology | Per-context relation R of names x concepts must be a bijection on preferred names; homonym = one name, 2+ concepts; synonym = 2+ preferred names for one concept | Two exact, decidable checks with counts H and S as metrics; no NLP | Curation of the registry; needs accepted-form (altLabel) escape hatch | adopt | [Deissenboeck-Pizka](https://teamscale.com/publications/2005-concise-and-consistent-naming.pdf) |
| Set theory, equivalence relations | Forms of a term form a class; canonical representative = preferred form; ties broken by lowest term id | Deterministic normalisation and rename targets | none | adopt | design (no source needed) |
| Order theory | `broader` as a partial order; check acyclicity; "affected terms" as a least fixed point via `domain/impact.py` | Term-change impact with the existing closure code | Reuse needs a small adapter | adapt | [SKOS S27](https://www.w3.org/TR/skos-reference/), `src/eija_studio/domain/impact.py` |
| Formal languages | A name is a word over the term alphabet plus separators; longest-match tokenisation over a sorted form table; regular, linear time | Deterministic term extraction from identifiers, UI text and prose | Same-case identifiers (`getcurrentuser`) are unsplittable without a dictionary; report UNKNOWN, never guess | adopt | design; [3D-Linter F5](https://github.com/RomanosTrechlis/3d-linter/blob/master/docs/SPEC.md) |
| Content-addressed Merkle | Each binding stores (`repo://` URI, hash method, hash); registry root = SHA-256 of canonical JSON | Detects "referenced text changed since baselined" | Hash change is not semantic drift; a stale flag is a prompt to re-review | adopt | okf `codelink.py`; [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785) |
| Incremental computation | Re-check only files in the diff plus files bound to changed terms; baseline ratchet for pre-existing violations | Fast agent loop; new debt cannot enter | Needs a differential test that incremental equals full | adapt | design |
| Bidirectional transformations | Views (OKF pages, glossary YAML, vocab files) are get-only lenses; edits detected by hash; renames are proposals | Single source, no round-trip conflicts | Manual edits to views are rejected, not merged | adopt (get-only) | [OKF SPEC section 6](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) |
| Relational algebra / Datalog | Bindings as relations; orphan and coverage checks as set differences | Clear semantics for reports | A Datalog engine is overkill for hundreds of facts | theory-only | other dossiers |
| Description logic (OWL) | Classification by reasoner | none for a closed glossary | RDF stack; open-world surprises | theory-only | [OWL 2 primer](https://www.w3.org/TR/owl2-primer/) |
| Closed-world shapes (SHACL) | Constraint shapes over the exported graph | Independent second implementation of the checks | rdflib, pySHACL; SHACL 1.2 still draft | adapt (optional cross-check) | [SHACL](https://www.w3.org/TR/shacl/) |
| Information theory | Entropy of name choice per concept | Explains why free naming diverges (6.9% agreement) | Adds nothing over the synonym count S for a gate | theory-only | [Feitelson](https://arxiv.org/abs/2103.07487) |
| Statistical learning | Name-consistency and name-suggestion models | Hints for agents and reviewers | 67.9% F1 detection: too many false positives to gate; version-dependent output | adapt (advisory) | [Liu](https://api.openalex.org/works/doi:10.1109/icse.2019.00019), [Allamanis](https://api.openalex.org/works/doi:10.1145/2635868.2635883) |
| Type theory (typed holes) | Unresolved concept as an explicit HOLE state rather than an error | Lets drafts exist without lying | Not needed for a plain registry | theory-only | [Hazelnut](https://api.openalex.org/works/doi:10.1145/3093333.3009900) |
| Category theory | Context map as partial maps between per-context term sets; composition must commute | Catches inconsistent translations | Only pays with 3 or more translating contexts; EIJA has 5 contexts, no declared translations | theory-only | design |

## 5. Implications for EIJA (concrete)

1. **Registry, not DSL.** Propose ADR-0089: a term record `{id, context, kind, definition, forms{preferred, accepted[], hidden[], forbidden[{form, replaced_by}]}, broader[], status, bindings[{uri, method, hash}]}`, canonical JSON, one file per context. Existing ARCHITECTURE.md definitions stay as prose and become bindings via `md-bold-term-v1`. ADR-0016 OSS check: Contextive/LinkML/SHACL considered; custom code is the schema, splitter and checker because no tool implements per-context bijection with declared bindings.
2. **Checks that fail the build (deterministic, near-zero false positive):** duplicate preferred form in a context (homonym, SKOS S14 analogue); a form used by two terms in one context; term with two preferred forms (synonym); forbidden or deprecated form at a declaration site; binding that does not resolve; cyclic `broader`; `deprecated` without `replaced_by`. **Reports only:** stale-hash bindings, unbound identifiers, unknown high-frequency words.
3. **Declared bindings, measured.** Probe on `src/` at ddc43b9 (502 distinct words, 598 distinct identifiers): terms as contiguous identifier words: Change Case 9 uses, Semantic Transaction 11, the other 8 terms 0. Actual code spellings are `Workflow`, `Preview`, `ReceiptSigner`, event string `"LocalDecision"`, kebab id `"review-packet"`, error text "Preview instance not found". Frequent code words absent from the glossary (`candidate` 22, `proposal` 26, `subject` 23, `principal` 23, `operation` 22) are glossary-candidate reports, not violations. 4. **Surface adapters (all pure functions of file bytes plus registry):** Python by `ast` def/class/arg/assign names; docs and ADRs by markdown-it-py AST excluding code; tests by function names and docstrings; UI by literal scan of `resources/*.html|js` (small today), moving to catalog ids only if it grows; diagrams by checking committed labels, while the visual lane generates them from the model. Keep two vocabularies apart: UL terms (types) versus Workflow instance ids such as states and roles (data).
5. **False-positive control kit:** exact token match after a pinned splitter; ASCII-only code-facing forms (avoids `casefold` differences across Unicode database versions); declaration sites only; per-context scope; diff-only gating with a baseline ratchet file; suppressions carry `id`, `reason`, evidence path (ProofMap GAP-017 shape) and no dates.
6. **Determinism.** Registry hashing must not reuse `models.canonical()` blindly: it sorts by Unicode code point, while RFC 8785 sorts by UTF-16 code units. I verified the two orders differ for U+FFFF versus U+10000. Registry values are strings and integers only, and the fingerprint is defined as `canonical()` output with that caveat stated, or use a JCS implementation. Golden vectors for the splitter (acronyms, digits, kebab, snake, PascalCase). Read and write files as UTF-8 explicitly (`cp1252` stdout broke my probe on Windows).
7. **Exports, each byte-identical and golden-tested:** OKF `type: Term` pages (okf lane), Contextive glossary, Vale and cspell vocab, SKOS Turtle, optionally CML. A missing optional tool reports NOT_RUN, never PASS. Vocabulary fingerprint is a candidate subject dimension for receipts; that is a kernel change needing its own ADR.
8. **Agents (MCP lane interface).** Read-only tools: `language.lookup(form)` returns term, context, definition, preferred form; `language.check(names[], context)` returns a verdict with `replaced_by`. Agents propose renames as patches (LibCST optional); a human decides. LLM naming suggestions stay in a separate advisory channel.
9. **Quality-lane interface.** Bounded contexts map to module groups for import-linter independence contracts; today the quality worktree has layer contracts only, and code is organised by layer, not context, so this is a later refactor question, not a v1 gate.
10. **Revisit triggers.** Adopt a language workbench (Langium first) only if guard/effect rules need a textual syntax with editor support and more than one author. Adopt SHACL as primary only if the registry grows past a few hundred terms with heterogeneous shapes. Add category-style translation checks when three or more contexts declare translations.
