# ADR-0149: Preview a semantic edit from one captured case revision

* Status: accepted for the local owner workbench
* Date: 2026-10-03
* Lane: integration

## Context

The workbench needs a before/after comparison before the owner submits a typed edit, with
a cancel path that leaves the persisted case untouched. The existing `edit_check` answers
policy legality against the working model, including a baseline before meaning selection.
Changing that result to include case edit readiness would break existing HTTP and MCP consumers.

## Decision

Add `Studio.edit_preview` and POST `/api/cases/{case_id}/edit/preview`. Keep `edit_check`,
its route and MCP contract unchanged. The preview endpoint takes the same typed transaction
input as the existing check. FastAPI/Pydantic validate the input and generate the response
schema; the normal local session, origin and JSON guards still apply. No MCP tool is added.

The application captures one validated Change Case and releases its database transaction.
`application/edit_preview.py` checks the same open-case requirement and semantic history
replay as `Studio.edit`, then calls the existing `apply_transaction` interpreter. It is a
projection adapter, with no new edit vocabulary, policy rule or interpretation engine.
History replay protects the atomic selected meaning and refuses an unexplained candidate.

The response contains `legal`, `codes`, `refs`, `case_id`, `version`, `stage`,
`semantic_hash`, the canonical typed `transaction`, the exact `current` Workflow and,
when legal, the exact `candidate` Workflow and its `candidate_semantic_hash`. Every identity
and model field belongs to the same captured case. `applied` and `persisted` are false;
`scope` is `semantic-edit-preview`. Policy/structure refusal uses the interpreter's codes
and references. Missing meaning, closed case or inconsistent history returns the corresponding
case refusal. Every refusal has null candidate and candidate hash, never a guessed model.
Malformed input and missing cases retain the ordinary transport error contracts.

The browser compares these two server models and displays an explicitly uncommitted preview.
Cancel discards only browser interaction state. Apply sends the echoed transaction and captured
case version to the existing owner `edit` route. That route repeats authority, case-version,
lifecycle, history and policy checks. Any intervening case change, including layout alone,
invalidates the captured version. The preview response grants no capability and reserves no
revision; a concurrent edit may make it stale immediately.

## Consequences and verification

Preview does not save a case, append audit, clear redo, invalidate a decision, alter layout,
touch either baseline, execute runtime actions or run verification. It supplies no receipt,
impact-completeness claim or evidence eligibility. Model source and repository source remain
separate. The normal edit still performs all actual persistence and decision invalidation.

Focused tests compare legal candidates against explicit expected model changes, install a
SQLite authorizer that rejects attempted data writes, compare every persisted table, preserve
synthetic history markers, exercise both domain packs and exact refusal references, and prove
stale versions are rejected without mutation. Tests also cover missing meaning, closed cases,
inconsistent history, invalid input, session/origin guards, and a concurrent revision after
capture. Existing policy-only HTTP/MCP checks retain their compact response and behavior.
The committed OpenAPI document is regenerated by FastAPI and checked against its generator.

This is engineering evidence for deterministic preview and edit boundaries. It does not prove
human comprehension, productivity or a complete consequence analysis of arbitrary software.
