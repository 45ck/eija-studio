# ADR-0097: Impact, ranking and evidence-status mathematics: fixed points, integer relevance, greedy selection, count vectors, and no confidence percentage

* Status: proposed
* Date: 2026-09-29
* Lane: weave (aspect impact-ranking-math; design in [docs/weave/design/impact-ranking-and-confidence.md](../weave/design/impact-ranking-and-confidence.md), oracles in [graph/schema/math-oracles.md](../../graph/schema/math-oracles.md))

## Context and problem statement

The weave graph must answer six questions about a change: what does it affect, what should an agent or a person read, which tests give the cheapest useful re-check, how should changes be queued for review, what is the status of a claim once several pieces of evidence exist, and how confident may anyone be. The kernel already has two of the ingredients: `domain/impact.py` (a least-fixed-point closure with a budget and an honest frontier) and `domain/evidence.py` (`aggregate_status`, which is order-independent on flat receipt lists; its rule, read as a fold on statuses, is not associative when its own output is fed back in: flat `CONFLICT`, rolled-up `FAIL`, MEASUREMENT under a patched `assess_receipt`, reproduced. The kernel does not roll up today: its one caller, `application/compiler.py`, folds a flat list. The hazard matters because the graph will roll up). Library defaults are not deterministic: `nx.condensation` numbered components 24 ways over 200 shuffles, and float PageRank differed in 40 of 40 shuffles (SYNTHESIS section 7). The determinism doctrine (rules D-01, D-07, D-10 of ARCHITECTURE section 7) bans exactly those behaviours, and the honest-label rules ban pseudo-precision.

Numbering note for the integrator: ARCHITECTURE section 11 allocates 0097 to "rule model" and 0101 to the status lattice, while this lane assignment gives 0097 to this record, and sibling aspects have already used 0089 (metamodel), 0091 (store), 0093 (consistency), 0095 (rules), 0099 (agent interface) and 0101 (human views) for other subjects than the table says. The table needs one reconciliation pass; this record cites sibling aspects by name and file, not by table number. It defines the status algebra and its tests; the kernel change request for `aggregate_status` (prevention of the roll-up hazard, not repair of a present defect) still needs its own record and PR.

## Decision drivers

* Same inputs give byte-identical outputs (D-01, D-04, D-07, D-10): no floats, no library-default order, no clock, no random source in an artefact.
* Every answer explainable by a witness a person can re-check; every truncation reported as a `frontier`.
* ADR-0016: adopt before building; build only the EIJA-specific glue and say why.
* A missing prerequisite is `NOT_RUN`, never `PASS`; a proof about a model is not a proof about code; no benefit to agents or people is claimed until measured.
* Efficiency at the scale of this repository (thousands to low hundreds of thousands of arcs, on a shared 16 GB PC).
* Hypotheses of any probabilistic method must hold, or the number is not printed.

## Considered options

1. **Use a graph database's algorithm library** (Neo4j GDS PageRank, connected components, shortest path). Rejected for the trust path: the repository's `LICENSE.txt` head says GNU GPL version 3, so it cannot be linked into an Apache-2.0 package; it is a stateful server outside git; its PageRank stops when scores change less than a float tolerance (defaults `maxIterations 20`, `tolerance 1e-7`, `dampingFactor 0.85`); and it offers no set cover, status algebra or witness. Kept as an optional one-way export a person may explore.
2. **Use networkx, scipy or rustworkx for SCC, PageRank and flow inside the product.** Rejected for artefacts: order-dependent labels and float results (measured). Kept: networkx as a test oracle that skips as `NOT_RUN` when absent.
3. **Use a Datalog engine (Soufflé) for closure and provenance.** Rejected as the default path: a C++ toolchain whose Windows build was not verified, and the closure is already the kernel's own least fixed point: the reference is tested equal to the kernel on 300 seeded graphs, and the SQLite recursive CTE is tested equal to the reference on the worked example and on 200 seeded typed graphs (networkx is used only for the SCC partition and the PageRank cross-check, not for the closure). Kept as an optional `.facts` export.
4. **Adopt an existing test-selection tool as the selector** (pytest-testmon, Ekstazi). Not adopted as the selector: its README saves a dependency database to `.testmondata` (a file outside the graph) and testmon.org says it collects dependencies with Coverage.py and compares them against changes, but the comparison rule (its blog post) was not read, so its selection is not shown to be a pure function of the graph and a change, which is the determinism requirement. History-mined co-change coupling, the best-established signal for what else changes, is deferred until EIJA has history (7 commits today); the offline study in the design (section 5.6) uses it only as ground truth for a ranking, not as a ranker. coverage.py (dynamic contexts) is adopted as the fact source for `covers` edges. A comparison on the same change sets is a phase 4 measurement.
5. **A probabilistic confidence layer** (conservative Bayesian inference, subjective logic, Bayesian updating, Assurance 2.0 probabilistic valuation). Rejected: subjective logic and Bayesian updating need a prior or base rate and independent sources, which do not hold for evidence from one agent and one tool, and three conventional uninformative priors give 0.857, 0.917 and 1.0 for the same five passes. Conservative Bayesian inference was not evaluated: the theorem hypotheses were not read, and from the abstract it works from operational-testing evidence and a prior, which EIJA lacks.
6. **A weighted scalar change-risk score.** Rejected: no ground truth (this repository has 7 commits), and a scalar becomes an optimisation target.
7. **A thin stdlib layer with a reference implementation and hand-verified oracles** (chosen).

## Decision outcome

Chosen option: "a thin stdlib layer with a reference implementation and hand-verified oracles", because it is the only option whose results are byte-reproducible on Windows and POSIX, whose every step has a witness or an error bound, and whose licence is unencumbered. Each decision has a section in the design document and an oracle in `math-oracles.md`.

| Id | Decision | Guarantee and hypotheses | Oracle |
|---|---|---|---|
| IR-1 | Impact is the least fixed point of `X -> C U succ(X)` over typed arcs in three soundness tiers (must, may, heuristic), with tier, distance, lexicographically smallest shortest-path witness, kernel-compatible budget, `complete` and `frontier`, computed over the union of base and head arcs | Order-independent, terminates, tiers nest; equals the kernel on 300 seeded graphs, the SQL form equals it on the worked example and 200 seeded typed graphs, and it is the least pre-fixed point exhaustively on tiny graphs. Reach is over encoded arcs only | O1 |
| IR-2 | Impact (structural, transitive) and suspicion (digest-driven, one hop, early cutoff) are separate; lint: every link type's flow covers its anchored direction, so stale nodes lie inside the impact set | Tested with a negative control | O1 |
| IR-3 | SCC condensation with minimum-member labels, lexicographically smallest topological order, reach and exposure counts by bitset DP; betweenness not built | `O(V+E)` labels, `O(E V / w)` all-node counts; identical under shuffles | O2 |
| IR-4 | Relevance is personalised PageRank in bit-exact fixed-point integers (`SCALE = 2^40`, floor split, remainder to sorted targets, `K` from `alpha` by integer inequality); default `alpha = 1/5`, impact-direction weight 2, reverse weight 1, hub damping optional and off; advisory only, never a gate | L1 error at most `2 SCALE beta^K + (arcs + 2 nodes + seeds)/alpha` units, checked against exact rational solutions; ordering certified when scores differ by more than twice that. Offline co-change study on two Python repositories: beats hop distance at recall@10 with paired 95% intervals excluding 0; ties path-prefix on one, beats it on the other. No agent or human effect is claimed | O3 |
| IR-5 | `context(budget)` = pinned seeds, then density greedy with a best-single-item safeguard, budget in bytes of rendered pages, `BUDGET_TOO_SMALL` instead of truncation, and an `omitted` list in which every candidate not chosen carries a reason (`NOT_SELECTED_BUDGET`, `TOO_LARGE_FOR_ROOM`, `NON_POSITIVE_SCORE`, `NON_POSITIVE_COST`) | At least half the optimum when values are additive and each cost fits (candidates that cannot fit are in no feasible set); exhaustive check on 200 instances; chosen and omitted partition the candidates on 200 instances | O4 |
| IR-6 | Test and evidence selection: a safe pool from coverage-derived `covers` edges (`NOT_RUN` without coverage data), then weighted greedy set cover of impacted obligations by exact cost per newly covered element; unreachable obligations are findings; fast tier only | `H(d)` approximation (Chvatal); greedy 3 against optimum 2 on the classic family; no better than about `ln n` in polynomial time unless P = NP | O5 |
| IR-7 | Change risk is a vector of eight exact counts with a partial order and a lexicographic review order; gates are boolean policy rules, never thresholds | Order never puts a dominated change above its dominator | O9 |
| IR-8 | Two status operators: replication join `A` over `UNKNOWN < STALE < {PASS, FAIL} < CONFLICT` for repeated observations of one check (the kernel's five values; empty fold `UNKNOWN`), and chain-minimum conjunction `B` with `PASS` on top for distinct checks; `NOT_RUN` lives only in `B`; the empty conjunction is `NOT_RUN`, never `PASS` | Laws checked exhaustively; `A` equals kernel `aggregate_status` on all 5460 flat sequences of length 1 to 6 and on the empty list, and composes where the kernel does not; `PASS` iff all `PASS` for every admissible chain. The order among non-`PASS` values stays an owner decision. Two representational differences from the formal aspect's `eijaref.status` are tested and left to the integrator with a recommendation | O7, O10 |
| IR-9 | No confidence percentage in any gate, default view, agent result or OKF page. Print counts and ratios, exhaustive-domain statements, generator-relative miss bounds labelled conditional, mutation ratios with the fault model named, `pass^k` with `n`, and an evidence summary | Exact rationals only; demonstrations in the oracle file | O8 |
| IR-10 | Evidence redundancy `k` (vertex-disjoint paths, cap 3) and the canonical source-side minimal cut; report only | Menger; cut brute-force checked | O6 |
| IR-11 | Changeset overlap (direct, reaches, shared, by tier) as pre-merge conflict prediction, an early signal that complements the consistency aspect's post-merge check | Symmetric; equals the intersection of two tiered impact sets | O11 |

Every function is a pure function of the canonical graph, recorded parameters and a change set, returns integers and sorted lists, and carries a `params` digest. A production implementation must reproduce the oracles byte for byte and is differential-tested against `graph/bench/impact_math_reference.py`.

### Interfaces (explicit)

Read on 2026-09-29 from sibling worktree files (parallel work; ADR numbers of aspects I have not seen are not cited):

* Metamodel aspect (ADR-0089, `graph/schema/metamodel.json`): no new field. Impact flow is derived from each link kind's `affects` and `anchor_ends`; `soundness` gives the tier; `rank_weight` and `cover_role` are read from the kind (validated; today every kind is `[2, 1]`, and `verifies` and `covers` are the only roles). A test fails on an unknown `affects` value or a changed weight or role. Open request: an optional `cost` attribute on verifier node types.
* Agent-interface aspect (ADR-0099): `graph_impact` is IR-1 (`by_soundness` = tiers 0, 1, 2; `max_nodes` = kernel budget; same witness rule). `context_pack` takes its mandatory set as the pinned set of IR-5 and its ranked tier from IR-4. **Open conflict:** that aspect specifies its own fixed-step integer PageRank (damping 0.85, `T = 30`, undirected, per-kind base weights); design section 5.7 compares it with IR-4 and recommends one implementation, `eijagraph.rank`.
* Human-views aspect (ADR-0101, `graph/schema/views.md`): consumes `tiered_impact`, `fold_a`, `fold_b`, `LIFT`, the set cover and the redundancy count under the names and shapes of the reference.
* Formal aspect (`graph/formal/eijaref`): second checker for closure certificates, SCC labels and topological order (differential tests); its status reference agrees on everything that decides a verdict and differs on two representational choices (design section 10.3).
* Consistency aspect (ADR-0093): roots come from the keyed diff of two roots; closure runs over the union of base and head arcs.
* Store aspect (ADR-0091): the `arc` view over its `edge` table and a generated `flow` table, with the closure query of oracle O1 tested against that schema; its `context` query should take bytes, not tokens. Rules aspect (ADR-0095): findings WV-005, WV-010, WV-014, WV-016 plus new rule ideas listed in the design document. Link and ledger and assurance aspects: `link_status` lifted by `LIFT`, `assess_link` outputs as `A` inputs.
* Existing lanes: okf (page bytes as context cost; ADR-0045, 0046), agents (ADR-0041), metrics (ADR-0037), mutation (ADR-0033, `fault_detection` attribute reported, never a probability), quality (ADR-0035, a `fast` session running the oracle tests), property (oracle tests reused as properties).

### Consequences

* Good: the blast radius, the ranking and the test set are reproducible byte for byte and each comes with a witness or a stated error bound; the fast-tier selection exposes impacted obligations that no test observes; the roll-up algebra that the kernel's rule would get wrong if reused is implemented and tested, ready for a kernel ADR (prevention); a missing tool cannot look green; no number claims more than its hypotheses allow.
* Good: no new runtime dependency (stdlib only); networkx and Hypothesis stay optional test tools.
* Bad: the impact set is as complete as the encoded arcs and every link type needs a flow declaration; relevance weights are heuristics and the co-change study is a proxy on two repositories (parameters chosen on the older half of the same repositories, variants within noise, hub damping helped one and hurt the other); the integer PPR is slow in pure Python (3.6 s at 50 000 arcs, MEASUREMENT); the fast tier is unsafe by design; there is no single risk or confidence number to show.
* Bad: the effect on agent success and on human review time is UNMEASURED; the ranking, selection and context tools ship as advisory until the eval design (pass^k with and without graph context, review-time study) reports.
* Revisit when: (a) `alpha`, weights or hub damping change the ranking on a third repository or on EIJA's own history once it has a few hundred commits; (b) all-node reach or PPR exceeds an agreed time budget on the reference PC (candidates: hop-bounded PPR, native integer PPR, lazy greedy); (c) a deployed component has real operating data and a decision ledger with outcomes large enough to score a forecast, at which point a calibrated confidence may be reconsidered; (d) POSIX runs disagree with the Windows goldens; (e) a selection tool (pytest-testmon or an RTS tool) beats the selector on the same change sets.
