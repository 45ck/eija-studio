# Whole-application IDE experience

Design specification, **2 October 2026**. This is an implementation target, not a screenshot of shipped functionality or an acceptance result. Read alongside the [mission](../engineering/MISSION.md), [IDE acceptance and UX rubric](../engineering/SELF-DOGFOOD-ACCEPTANCE.md), [personas and stories](WHOLE-APP-STORIES.md) and [design concepts](README.md). The complete supported IDE must work outside a recorded path. EIJA itself is the first connected project; external adoption follows acceptance.

## Product contract

The primary users understand UML and software design and increasingly build with agents. Support prompt-first and model-first work in one persistent, non-linear environment. The engineer can start at a concept, source reference, proposal, changed rule or failed check and return without losing context. Source is readable and navigable; **code authoring stays in the engineer's existing editor or coding agent**. Model editing and repository-source modification must never look interchangeable.

Carry a shared selection across surfaces: repository snapshot, case/change, baseline and candidate model identities, selected concept and evidence subject. Show short readable identities with full details on demand. Never carry a previous case's selection, approval or green status into another case. A generated diagram, parser fact, explicit binding, runtime observation and AI hypothesis must have distinguishable provenance. Unresolved mappings remain visible.

Use a consistent shell: project/command bar; searchable model/project explorer; central editor tabs with optional compare view; contextual inspector; problems/evidence/history panel; persistent source/model/agent status. Panels can be resized or collapsed and must restore usable proportions. Shell layout is presentation state, not a second model. Tasks open views; they do not advance wizard steps. Owner-only decision actions remain separate from agent proposals and technical checks.

## Screen-state map

Every state below needs a populated, empty, loading, refused/error and stale variant where applicable. IDs connect this plan, concept images and executable stories. Navigation must preserve the subject and offer a return to origin.

| ID / surface | Main content and actions | Connections and failure behavior |
|---|---|---|
| **S01 Workspace/model** | Searchable language/DDD tree; diagram and rule views; selected state/transition inspector; zoom, fit, reveal selection; current model revision | Open S04 source, S05 edit or S06 rule evidence from the selected element. Empty models explain what can be imported or proposed. Layout failure leaves the rule editor usable. |
| **S02 Intent/agent proposal** | Request, explicit scope, agent/provider identity, pending/completed/failed activity, interpretations, unknowns and changed concepts | Open S03 comparison before deciding meaning. Retain a failed request for correction; no silent retry or extra spend. Offline fixture and live-agent activity must look different. Proposals do not choose meaning or gain authority. |
| **S03 Visual change review** | Baseline/candidate diagrams and concise semantic changes; added/removed/changed badges; before/after guard, role, endpoint and meaning; known impact paths and unsupported coverage | Link each change to S01 element, S04 exact source and S06 affected check. Preserve corresponding node positions in comparison when practical; never fabricate identity correspondence. Distinguish model change from observed repository change. Missing source mapping stays unknown. |
| **S04 Source and connection** | Read-only file/symbol view; line range, captured revision/content digest, extraction method, bindings, included/excluded inventory and refresh status | Navigate model → source → model with selection retained. A changed snapshot marks old links/evidence stale. Missing files, binary/unsupported/dynamic behavior explain the limitation; do not open a guessed location or execute the target project. |
| **S05 Rules/refactor preview** | Editable supported rule fields or diagram gesture; explicit before/after transaction; affected concepts, evidence and source bindings; check, cancel, submit | Use server affordances and version checks. An unsafe or stale edit shows the real reason, preserves the last valid model and supports correction. Rename/split/merge/code-generation operations remain unavailable until their typed semantics and adapters exist. No cosmetic preview implies a source rewrite. |
| **S06 Evidence and counterexample** | Per-property result, bounds, assumptions, subject and tool identity; witness/counterexample stepper; missing/stale evidence; raw artifact link | Select a failed law → highlighted model step → S04 binding or S07 runtime witness. UNKNOWN/NOT_RUN/PARTIAL/FAIL remain distinct. Source review and human-validation status cannot be hidden in a collapsed success summary. |
| **S07 Runtime/try** | Actual supported candidate state, synthetic actor/context, permitted actions, committed result and audit/effect trace | Action success appears only after the committed server result. Refusal preserves state and highlights the relevant rule; return to S05 or S06. Simulation, test harness and real application observations have explicit labels. |
| **S08 History/recovery** | Revision/case timeline; selected comparison; saved checkpoints; provenance; discarded/rejected changes; exact reviewed subject | Return to S03 comparison or current work. Cancel unsent edits immediately. Any restore/undo creates the appropriate server-checked revision and preserves history; otherwise offer inspection without a fake restore control. Failed refresh must not erase the last valid view. |
| **S09 Parallel-agent workspace** | Planned session/worktree ownership, base revision, changed abstractions/files, dependencies and semantic overlap; combined-result checks and landing status | Planned expansion: select conflict → S03/S04; inspect exact merge result → S06. File overlap and semantic conflict are different. Never infer safe landing from branch-only checks, an agent's summary or an animation; no queue controls before the authority/integration contract exists. |
| **S10 Connection/help/recovery** | First connection, no case, unconfigured provider, unavailable tool, disconnected server, partial index, permissions/refusal and help | Offer one relevant next action with preserved context: configure, retry explicit operation, inspect details or return to last snapshot. State whether anything changed. Show unsupported scope without forcing an irrelevant onboarding wizard every session. |

Non-linear journeys: **model-first** S01 → S05 → S03 → S06 → S08; **agent-first** S02 → S03 → S04 → S06; **source-first** S04 → S01 → S03; **failure/recovery** S05/S07 → S06/S10 → corrected S05 → S08. Each returns to its entry selection. S09 is a separate planned factory journey, not an implied current release capability.

## HCI criteria and failure controls

Extend the existing [HCI instruments](../hci/README.md), [raw-evidence conventions](../hci/REPORT.md) and budgets; do not create parallel formulas. Predictions rank design choices; they do not measure a user's understanding. The older 20-action excursion journey does not cover this whole IDE. New journeys need their own declared task/choice groups and observations before new results can be claimed.

| ID / principle | Concrete criterion and observation | Failure to catch |
|---|---|---|
| H01 Fitts / target acquisition | Audit actual clickable boxes: zero unjustified failures of the existing 24 CSS-pixel minimum/spacing check; favor larger frequent/destructive controls. Measure centre and nearest-edge travel for selection → edit → review; keep contextual actions near the selection. Record long moves rather than hiding targets from the audit. | Tiny edge handles or distant submit controls; canvas gestures with no keyboard equivalent. |
| H02 Hick-Hyman / choice | Declare competing actions per intent. Existing instrument flags groups over seven; use context and searchable commands when a real group grows. Keep editor navigation stable. Test a first-time reviewer finding the next relevant action without inspecting every toolbar. | Treating the entire IDE as one choice set, arbitrary seven-tab limits, or hiding necessary actions behind unexplained icons. |
| H03 Gestalt / diagram organization | Group concept properties, consequences and evidence with proximity and explicit headings. In S03 keep baseline/candidate orientation, legend and identity consistent; review long labels, self-loops, parallel edges and dense neighborhoods at fit and zoom. No overlapping labels, ambiguous arrow endpoints or color-only difference. | Attractive grouping suggests nonexistent containment/authority; re-layout makes an unchanged model look changed. |
| H04 Recognition / progressive disclosure | Keep selected concept, current/baseline identities, impact count with coverage and blocking status visible. Summaries open exact source, assumptions and raw evidence in one action; provide labels/tooltips and stable names. Compare two changes without memorizing hidden IDs. | Collapsing UNKNOWN or source-review blockers to make a green summary; deeply nested evidence or icon-only commands. |
| H05 Cognitive load / KLM | Reuse the existing journey/operator recorder to compare equivalent tasks and keyboard/pointer paths. Count unnecessary re-entry, homing, repeated search and focus restoration. Treat visible chunk counts as a diagnostic proxy, not a rule that a professional IDE may show only four or nine objects. | Optimizing a proxy by hiding useful context, relabeling predicted seconds as measured productivity. |
| H06 Status / latency | Preserve measured median/IQR/p95/max and environment. Existing settled-DOM target is 400 ms; the 4000 ms tail ratchet is a legacy regression guard, not a desirable UX target or universal Doherty law. Measure new per-action classes with frame/paint-aware observations: first DOM mutation alone is insufficient. Long operations show honest pending/progress, duplicate prevention and cancel/abandon semantics. | Spinner updates score well while the screen stalls; an index refresh clears context; double activation causes two effects. |
| H07 Control / error prevention and recovery | Preview consequential model edits and exact subject; support cancel before submission, version refusal and recoverable failure. Return focus to the invoking control or the relevant error. Exercise interrupted request, stale source, forbidden operation and repeated click. Retain server audit/history. | UI-only undo, losing typed work after failure, silent rollback or approving a different revision. |
| H08 Consistency / real-world language | Use the same names for concepts, roles, actions, statuses and authority across tree, graph, rule editor, source and evidence. One status vocabulary has text plus icon/shape; concise error says what failed, whether state changed and the next permitted action. | Same green badge means checked, approved and applied; agent explanation silently replaces domain vocabulary. |
| H09 Accessibility / flexible operation | Run axe on every new state and inspect incomplete findings. Resolve serious/critical findings; keyboard journeys require zero unintended focus loss, visible focus, no trap, accessible names and announcements across tree, tabs, palette, canvas alternative, source, trace and recovery. Inspect contrast, text enlargement, screen-reader output, reduced motion, high contrast and reflow at the existing 390×844/320×568 probes; a two-dimensional diagram may pan, surrounding controls/evidence must remain reachable. | Clean axe report mistaken for WCAG conformance; scroll region or drag-only transition is unreachable; status conveyed only through color. |
| H10 Minimal presentation / help | Show task-relevant defaults while preserving power-user commands. Empty/partial/error states explain scope and offer contextual help. Test narrow panels, long names and zoom without clipped critical content. Add shortcut hints and explain check vs decide vs apply where it affects the decision. | A polished empty shell; hidden unsupported action; giant generic warning crowds out the actual task. |

These rows operationalize Nielsen's visibility, real-world match, user control, consistency, prevention, recognition, flexibility, minimalism, error recovery and help heuristics. Use them as review questions with recorded findings, not an automatic score proving usability. Keep current target/ratchet semantics: PASS, GAP, FAIL and NOT_RUN are distinct; do not loosen budgets to bless a redesign.

The historical instrument can report an aggregate PASS while individual metrics remain GAPs; one serious axe rule and seven focus losses were allowed by its ratchets. Those allowances do not satisfy this IDE release bar. Create task-specific baselines for new journeys rather than inheriting the old seven-move allowance or 65-second KLM total. Gestalt has no implemented scalar score, and chunk counts do not measure cognitive load. Audit the complete shipped asset identity, including nested vendor files, when refreshing evidence; rederiving a report from old observations is not a new browser run.

Apply the existing proposed motion design as **unmeasured requirements**: direct feedback p95 target/limit 50/100 ms; view updates 200/1000 ms; commits 300/1000 ms; job acceptance 50/100 ms, with no invented completion deadline. Collect at least 30 trials per action class in three repetitions, record environment/visibility and keep legacy DOM metrics separately. These are project targets and fail rules, not demonstrated human thresholds. Show pending locally; RUNNING/progress and terminal authority/evidence states require server information. Abandoning a wait cannot promise cancellation or undo. Preserve prior evidence visibly with correct freshness, not a fake success animation. Reduced motion must preserve the same final meaning.

For constrained gestures apply steering-law reasoning: wide resize/connection targets, no narrow mandatory cursor tunnels, and a form/keyboard route. For information search give destinations concrete names and source/evidence counts with coverage, so users can recognize where to look. Test whether reviewers detect a seeded critical change and false alarm separately; visual emphasis or an attractive diagram is not evidence of accurate comprehension.

## Components and high-fidelity handoff

Keep the current Python/FastAPI/Pydantic kernel and browser delivery. Start with native accessible HTML controls, CSS grid/flex and existing UI modules. The integration's Dagre layout adapter owns graph geometry, Mermaid owns generated diagrams, and EIJA adapters own selection/typed transactions. Reuse Playwright/axe and the HCI journey recorder. These are existing project choices, not a new dependency recommendation or a claim that their integration has passed.

Use the [OSS register](../oss/REGISTER.md) before changing a component. Evaluate an established accessible tab/tree/split-pane or graph library only for a documented gap that native/current components cannot meet; compare accessibility, CSP, licensing, maintenance, bundle/build cost and replacement path. No framework rewrite, custom graph engine, solver or duplicated browser interpreter merely to match a picture. Source syntax presentation stays read-only; a full embedded code editor is outside the chosen form factor.

For **every S01–S10 surface**, the design handoff needs: populated and failure/stale states; the shared subject and selected item; actual controls and keyboard order; panel sizing at 1440×900 and 1280×800 plus enlargement/reflow probes; transition annotations; responsive/collapsed behavior; and story IDs. Show before/after model changes explicitly in S03. High fidelity means specified interaction and recovery, not only a detailed still. Generated imagery remains labeled **DESIGN CONCEPT**, with illustrative rules/status and no claim of execution. Root concept assets are indexed in the [design reference](README.md).

Complete in dependency order: shared subject/navigation/status → S10/S01/S04 → S02/S03/S05 → S06/S07/S08 → cross-surface UX and clean-checkout replay → real-app recordings. S09 requires its own worktree/authority/conflict/combined-result contracts. Update the [story matrix](WHOLE-APP-STORIES.md) from retained results. One writer integrates disjoint patches; reuse existing worktrees. No screen is accepted from source inspection, a passing unit test or a generated image alone.
